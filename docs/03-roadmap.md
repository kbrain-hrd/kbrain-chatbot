### 검색 방식 참고

벡터 검색만 쓴다면 `R02-Q05` 같은 문항 번호나 정확한 기술 용어를 놓치므로,
검색을 도입한다면 BM25(키워드)를 함께 쓰는 하이브리드여야 합니다.
다만 규모가 작으면 검색 없이 문항 목록 기반 특정+조회로 충분할 수 있어 방식 자체는 보류 상태입니다.

## 단계별 계획

각 단계는 **검증 조건을 통과해야 다음으로 넘어갑니다.**

### 1단계 — PDF → 마크다운 변환

- 문제 / 해설 / 답안지 변환
- 코드블록, 수식, 표 보존 확인

**완료 조건:** 원본 대조 검증 통과. 코드·수식 무결성 확인.

### 2단계 — 문서 구조화 및 색인

- 문항 단위 분리, 앵커 부여 (`R01-Q03`)
- 하이브리드 색인 구축

**완료 조건:** 문항 단위 분리 정확도 확인. 누락·중복 0건.

### 3단계 — 질문 분류 + 근거 검색

- 문제 관련 / 운영 관련 / 분류불가 판정
- 문제 특정 정확도 확보

**완료 조건:**
- **문제 특정 정확도 ≥ 99%** (여기가 틀리면 이후 전부 무의미)
- 근거 검색 Recall@5 ≥ 90%

### 4단계 — 초안 생성 + 검증 게이트

- 블라인드 풀이 → 해설·답안지 대조
- 플래그 판정 (해설불일치 / 근거부족)
- 교재 기준 + 현재 기준 병기

**완료 조건:** 실제 질문 30건 이상으로 초안 품질 확인. **오답을 확신 있게 제시한 건수 0.**

### 5단계 — 구글시트 연동

- 질문 입력 감지 → 초안 기록
- 상태 전이 처리

**완료 조건:** 질문 감지 → 초안 기록 왕복 동작 확인.

### 6단계 — 검수 승인 흐름

- 검수 대기 알림
- 승인 시 최종답변 자동 등록

**완료 조건:** 승인 → 등록 흐름 정상 동작. 실사용자 테스트 통과.

## 검증 기준

| 항목 | 기준 | 이유 |
|---|---|---|
| 문제 특정 정확도 | ≥ 99% | 틀리면 이후 처리가 전부 무의미 |
| 근거 검색 Recall@5 | ≥ 90% | 근거가 안 잡히면 답변 불가 |
| 확신 있는 오답 | **0건** | 가장 위험한 실패 유형 |
| 초안 무수정 승인률 | 측정 | 자동화 확대 판단 근거 |

**못 답하는 것은 허용, 틀린 답을 확신 있게 제시하는 것은 불허.**

## 비용 개산

질의 1건당 (문제 관련, 근거 + 블라인드 풀이 기준)

- 입력: 문제 원문 + 해설 + 프롬프트
- 출력: 답변 초안 + 대조 결과
- **대략 건당 50~100원 수준**

변수:
- 프롬프트 캐싱 적용 시 하락
- 독립 다중 풀이 적용 시 배수 증가
- 운영 질문은 근거가 짧아 더 저렴

정확한 수치는 실제 문제 길이를 확인한 뒤 재산정합니다.
