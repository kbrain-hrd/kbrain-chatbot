## 2. 미결정 사항

### 2-1. 검수를 어디서 할 것인가

> 상태: **결정 (2026-08-01).** 승인은 슬랙, 수정은 시트.

당초 권장안은 "슬랙은 알림만, 검수는 시트에서"였으나 뒤집혔습니다.
**승인 행위 자체가 슬랙에서 일어납니다.**

```
시트에 질문 등록
      ↓ (감지)
슬랙 카드: 초안 전문 + 근거 + 플래그 + [승인] [반려] + 시트 링크
      ↓
그대로 OK  → 슬랙에서 승인 → 시트에 최종답변 등록
손볼 게 있음 → 시트 링크로 이동해 수정 후 승인
```

**왜 이렇게 나눴는가.** 검수 결과는 승인 / 수정 후 승인 / 반려 세 가지인데,
슬랙 버튼은 승인·반려에는 빠르지만 **긴 답변을 고쳐 쓰기에는 불편**합니다.
그런데 초안이 항상 완벽할 수는 없으므로 실사용에서는 "수정 후 승인"이 가장 잦을 것으로 봅니다.

→ 승인 경로는 슬랙 하나로 유지하되, **수정만 시트로 넘깁니다.**
알림을 보고 다시 시트를 열어 상태를 찾아 들어가는 왕복을 없애는 것이 목적입니다.

### 2-2. 운영 관련 자료의 형태

> 상태: **해소 (2026-08-01).** 자료 수령으로 자동 해결.

문서 파일 형태로 4종 수령했습니다 — 준비안내(hwpx), CBT 가이드(PDF),
종합안내서(PDF), 셀프학습가이드(HTML). "정리된 것이 없어 문서화부터 해야 하는" 상황은
아니었습니다. 추출 난이도와 우선순위는 [05-data-survey 5장](05-data-survey.md) 참조.

### 2-3. 3과목(자동화) 질문 처리

3과목은 단답 정답이 없고 루브릭으로 채점합니다. 삼각 검증 구조가 성립하지 않습니다.

질문도 "정답이 뭔가요"가 아니라 "이렇게 만들면 점수 되나요"에 가까워,
근거가 정답이 아니라 채점 기준표입니다.

- 루브릭 항목을 근거로 제시하는 별도 경로가 필요
- 산출물 판정은 사람이 해야 하므로, 초안은 "기준 안내"까지만

> 상태: 미결정 (4단계 전 결정)

### 2-4. AI 사용 규정 — 자료 충돌이 아니라 대상이 달랐다

4단계 초안 검증 중 챗봇이 자료 간 충돌을 발견했고, 운영 담당자 확인으로 해소됐습니다.

| 자료 | 내용 | 실제 대상 |
|---|---|---|
| CBT 가이드 | "모든 문항 외부 도구(생성형 AI) 사용 가능" | **수행평가** |
| 보안서약서 5번 | "객관식·단답형·서술형에서 AI 도구 사용 금지" | **이러닝 학습평가** |

**둘 다 맞는 말이고 가리키는 시험이 달랐습니다.** 이러닝 학습평가는 자기주도형·기관맞춤형에만
있고 AI 사용이 금지되며, 그 뒤 수행평가 작업형 문항에서는 AI를 쓸 수 있습니다.

> 상태: **해소 (2026-08-01).** `content/operations/운영진확인사항.md` 에 기록.

### 2-5. 실전 세트 문의 대응

수령한 자료는 전부 "연습세트(정답·해설 공개)"입니다.
실전 세트 문제에 대한 질문이 들어올 경우의 방침이 필요합니다.

**운영 담당자 확인 (2026-08-01):** 평가 문제 형식은 연습문제와 **유사하지만**,
**연습문제는 연습문제일 뿐이고 실전은 다른 문제로 출제**됩니다. 유형·형식이 비슷할 뿐
같은 문제가 나오지 않습니다.

→ "연습문제와 똑같이 나오나요" 유형의 문의에는 이렇게 안내하면 됩니다.
실전 세트 문제 자체에 대한 문의는 자료가 없으므로 여전히 사람에게 넘깁니다.

> 상태: **부분 해소.** 형식 유사성은 안내 가능. 실전 문제 내용 문의는 근거 없음.

### 2-6. 문의 이력 2,046건을 어디에 쓸 것인가

2026-08-03 수령분에 챔피언 관련 상담 이력이 2,046건 있습니다
([05](05-data-survey.md) 7-2). 기존 골드셋 151건의 13배지만 용도가 갈립니다.

| 용도 | 판단 |
|---|---|
| **FAQ 보강** — 반복 문의를 추려 운영 근거로 편입 | 가장 값이 큽니다. 지금 `근거부족` 플래그의 상당수가 이런 일반 운영 문의입니다 |
| **골드셋 확대** — 분류 정확도 측정 | 레이블이 없어 사람이 달아야 합니다. 151건으로 이미 100%/100%라 추가 이득이 불확실합니다 |
| 답변 문체 학습 | 실익 대비 개인정보 취급 위험이 큽니다 |

→ **FAQ 보강만 하는 쪽으로 기웁니다.**

**다만 선별 방법에 대한 가정이 실측에서 깨졌습니다.** "빈출 주제로 묶으면 확 줄겠지"를
전제했는데, 3-gram 유사도로 묶어 보니 1,768건 중 3건 이상 반복되는 주제가 덮는 것이
**69건(4%)** 뿐입니다. 문의 본문이 개인 상황 서술이라 주제가 같아도 텍스트가 전부 다릅니다.

→ 기계적 중복 제거로는 줄지 않고 **LLM이 1,768건을 읽어 주제를 뽑아야** 합니다.
그게 "정리"의 실제 비용입니다.

> 상태: 미결정. 다만 **프롬프트 크기는 더 이상 제약이 아닙니다** — 운영 섹션이
> 검색으로 바뀌어(2-7) 몇 건을 넣든 판정 프롬프트는 top-12로 고정됩니다.

### 2-7. 운영 섹션 검색 도입 (결정)

> 상태: **결정 (2026-08-03).** 문항은 전량 적재 유지, 운영만 BM25 검색.

카탈로그가 커질수록 앞쪽 규칙이 묻히는 현상이 실측됐습니다 (2.2K 늘자 등급 유추 재발).
자료가 계속 들어오는 프로젝트라 이 추세를 방치할 수 없습니다.

| | 문항 | 운영 |
|---|---|---|
| 검색으로 가를 수 있나 | **안 됨** — 그린·블루는 숫자만 다르고, 되묻기를 top-N으로 표현할 수 없음 | 됨 — 등급 개념도 되묻기도 없음 |
| ⚠️ 정답 오류 경고 | 전량 적재라 **매 질의 항상 보임** | 무관 |
| 결론 | 전량 적재 유지 (7.5K) | **BM25 top-12** (6.8K → 0.9K) |

골드셋으로 견준 결과 **정확도는 동등**했습니다 (세트·과목 15/15, 등급 15/15 유지,
캐시읽기 513K → 288K). 운영 문의 8건 별도 확인에서도 8/8 정확한 앵커를 골랐습니다.

`--full` 플래그로 언제든 전량 적재와 견줄 수 있게 남겨 뒀습니다.

### 2-8. 의미 검색 추가 (결정)

> 상태: **결정 (2026-08-03).** BM25 단독 → BM25 + 로컬 임베딩 융합.

BM25만으로는 낱말이 어긋나는 질문을 놓쳤습니다. 로컬 임베딩(`multilingual-e5-small`,
471MB)을 얹고 **순위로 융합**(RRF)했습니다. 점수를 직접 더하지 않는 이유는 BM25는 상한이
없고 코사인은 -1~1 이라, 정규화 없이 더하면 한쪽이 먹기 때문입니다.

| 질문 | BM25 | 의미 | 융합 |
|---|---|---|---|
| 시험 떨어지면 다시 볼 수 있나요 | 9위 | 2위 | 3위 |
| 웹캠 대신 휴대폰 써도 되나요 | 6위 | 1위 | 2위 |
| 몇 점 이상 받아야 합격인가요 | 6위 | 1위 | 1위 |
| **75점 기준이 맞나요** | **1위** | **3위 밖** | **1위** |

**의미 검색 단독으로 가지 않은 이유가 마지막 줄입니다.** 임베딩은 숫자를 의미로 처리하지
못해 "75점"을 놓칩니다. 반대로 BM25는 "떨어지면 다시"를 못 잇습니다. 서로 못 하는 일이
달라서 둘 다 필요합니다.

**색인만 청킹하고 마크다운은 쪼개지 않았습니다.** 섹션 길이 편차가 커서
(중앙값 94자 ↔ 최대 20,040자) 긴 섹션은 벡터 하나로 뭉개집니다. 600자로 나누되
(119섹션 → 289청크) 앵커는 섹션 그대로 돌려줍니다 — 마크다운을 쪼개면 앵커가 바뀌어
골드셋 레이블과 문서 참조가 깨집니다.

**도입 과정에서 검색의 부작용이 실제로 나타났습니다.** "첨부 파일이 누락된 것 같습니다"
라는 문항 문의에 의미 검색이 "교육 신청·접수" FAQ 4개를 그럴듯하게 끌어왔고,
그 탓에 문항이 운영으로 기울어 세트·과목이 3회 중 2회 틀렸습니다.
검색 결과에 **"무관한 항목이 섞여 있다"**고 명시해 해소했습니다 (6/6 복구).

골드셋 최종: 세트·과목 15/15 · 등급 15/15 · 분류 20/21.
기동 시 색인 구축에 약 30초가 걸려 웹은 `startup` 에서 미리 세웁니다 —
첫 요청 때 하면 통화 중인 담당자가 그 30초를 기다리게 됩니다.

## 3. 확정된 사항

기록용으로 남깁니다.

| 항목 | 결정 |
|---|---|
| 정답의 근거 | 문제 원문 (해설·과거답변은 검수 대상) |
| 자동 발송 여부 | **하지 않음.** 사람 승인 후 등록 |
| 최종 저장소 | 구글시트 |
| 알림 채널 | 슬랙 |
| **질문 유입 경로** | **시트 + 유선(전화).** 둘 다 대응 (2026-08-01 추가) |
| **주력 질문 유형** | 오답 원인 문의 · 문제 오류 제기 · 운영 문의 · 3과목 산출물 문의 |
| **문제 오류 제기 처리** | **자동 판정 금지.** 대조 결과만 제시하고 사람에게 |
| **1.5단계 검증 방식** | 해설 코드 실행 → **문제지만으로 푸는 검증**으로 교체 |
| **시트 개인정보** | **질문·답변만 추출.** 이름·소속·연락처·이메일 컬럼은 읽지 않음 |
| **공식 정답 오류 처리** | 임의 정정 금지. `official_answer_disputed` 플래그 + 경위 안내 |
| **유선 대응 인터페이스** | **웹 UI.** 담당자가 여러 명이라 CLI는 부적합 |
| **검수 위치** | **승인은 슬랙, 수정은 시트** (2-1) |
| 교재 vs 현재 기준 충돌 | 교재 기준 정답 + 현재 기준 병기 |
| 문서 포맷 | PDF → 마크다운 전환 |
| 근거 없을 때 | 초안 생성하지 않고 담당자에게 알림 |
| 과목 | AI |
| MVP 범위 | **문제 관련 + 운영 관련 모두 포함** (2026-08-01 결정. 운영 자료 수령 완료) |
| 검색 구조 | **벡터 검색 미사용.** 앵커 기반 특정+조회 (문항 100개 규모 — [05](05-data-survey.md) 2-3) |
| 임베딩 모델 | 불필요 (검색 구조 결정에 따라 자동 해소) |
| 앵커 스킴 | `G-S01-M02-Q03` (등급-세트-과목-문항). 등급 필수 |
| PDF 추출기 | 문제지·해설은 **pypdfium2**. **답안지는 두 추출기 결과 병기 후 사람이 확정** — 둘 다 서로 다른 방식으로 틀림 ([05](05-data-survey.md) 3-1) |
