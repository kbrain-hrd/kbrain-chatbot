# 미확정 사항

구현 시작 전 확인이 필요한 항목입니다.

---

## 1. 필요 자료 (미수령)

| 자료 | 상태 | 필요한 이유 |
|---|---|---|
| 셀프스터디 PDF (문제) | ❌ 미수령 | 1단계 변환 시작에 필수 |
| 셀프스터디 PDF (해설·답안지) | ❌ 미수령 | 대조 검증에 필요 |
| 구글시트 URL + 접근 권한 | ❌ 미수령 | 현재 컬럼 구조 확인, 연동 |
| 운영 관련 자료 | ❌ 미수령 | 운영 질문 근거 |
| 첨부파일 목록 | ❌ 미확인 | 처리 방식 결정 |

**문제 PDF만 있어도 1단계는 시작 가능합니다.**

---

## 2. 미결정 사항

### 2-1. 검수를 어디서 할 것인가

| 안 | 장점 | 단점 |
|---|---|---|
| **시트에서 직접** (권장) | 긴 답변과 근거를 한눈에 보며 수정. 도구를 늘리지 않음 | 실시간성은 알림에 의존 |
| 슬랙 버튼 | 빠른 승인/반려 | 긴 답변 수정에 불편 |
| 별도 검수 화면 | 문제 원문·해설·초안을 나란히 표시 | 개발 범위 증가 |

**권장:** 슬랙으로 "N건 검수 대기" 알림만 받고, 검수는 시트에서 수행.

> 상태: 미결정

### 2-2. 운영 관련 자료의 형태

문서 파일 / 구글시트 / 노션 / 정리된 것 없음 — 어느 쪽인지에 따라
수집 방식과 작업량이 크게 달라집니다.

"정리된 것이 없다"면 자주 나오는 운영 질문부터 문서화하는 작업이 선행되어야 합니다.

> 상태: 미결정

### 2-3. 검색 구조 — 하이브리드 vs 단순 특정+조회

당초 하이브리드(벡터+BM25)로 계획했으나, 규모에 따라 더 단순한 방식이 가능해 보류.

| 안 | 내용 | 적합 조건 |
|---|---|---|
| 단순 특정+조회 | 전체 문항 앵커·제목 목록을 Claude에 주고 문항 특정 → 해당 md 직접 로드 | 문항 수백 개 이하, 질문이 특정 문항을 가리키는 경우 |
| 하이브리드 검색 | 벡터 + BM25 색인 구축 | 문항 규모가 크거나, 운영 자료처럼 문항 구조가 없는 문서 |

판단에 필요한 정보:
1. 전체 문항 규모 (PDF 확인 시 해소)
2. 기존 시트 질문에서 문항번호가 명시되는 비율
3. 운영 자료의 형태·분량 (운영 질문은 문항 구조가 없어 검색이 필요할 가능성 높음)

구현상 retrieval은 모듈로 분리해 두 방식 교체가 가능하게 하고, 2단계에서 실데이터 확인 후 결정.

> 상태: 보류 (2단계 전 결정)

### 2-4. 임베딩 모델

한국어 + AI 기술용어 혼재 환경에서의 성능을 실측한 뒤 결정합니다.
후보를 골드셋으로 비교 평가할 예정.
단, 2-3에서 "단순 특정+조회"로 결정되면 임베딩 자체가 불필요해집니다.

> 상태: 2-3 결정에 종속

### 2-5. 문항 규모

전체 회차 수, 회차당 문항 수를 확인해야 색인 구조와 비용을 산정할 수 있습니다.

> 상태: PDF 확인 시 자동 해소

## 3. 확정된 사항

기록용으로 남깁니다.

| 항목 | 결정 |
|---|---|
| 정답의 근거 | 문제 원문 (해설·과거답변은 검수 대상) |
| 자동 발송 여부 | **하지 않음.** 사람 승인 후 등록 |
| 최종 저장소 | 구글시트 |
| 알림 채널 | 슬랙 |
| 교재 vs 현재 기준 충돌 | 교재 기준 정답 + 현재 기준 병기 |
| 문서 포맷 | PDF → 마크다운 전환 |
| 근거 없을 때 | 초안 생성하지 않고 담당자에게 알림 |
| 과목 | AI |
| MVP 범위 | **문제 관련 + 운영 관련 모두 포함** (2026-08-01 결정. 단, 운영 자료 확보가 선행 조건) |

## 4. 남은 리스크

| 리스크 | 대응 |
|---|---|
| PDF 변환 시 코드·수식 손상 | 1단계 원본 대조 검증 필수 |
| 문제 자체에 오류가 있는 경우 | 삼각 검증에서 "전부 갈림"으로 탐지 → 사람 확인 |
| 검수 부담이 수기 작성보다 커지는 경우 | 초안 무수정 승인률을 측정해 판단. 낮으면 범위 축소 |
| 운영 자료 부재 | 운영 질문은 초기 범위에서 제외하고 문제 관련만 우선 적용 |
