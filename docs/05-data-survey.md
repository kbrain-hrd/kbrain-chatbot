## 2. 설계 가정과 실제의 차이

### 2-1. "회차"가 아니라 "등급 × 세트 × 과목"

설계 문서는 `round-01/`, 앵커 `R01-Q03` 을 가정했으나 실제 구조는 3층입니다.

```
등급(2: 그린·블루) × 세트(5) × 과목(3) = 30개 단위
각 단위 = 문제지.pdf + 해설.pdf + 답안지.pdf + 첨부/
```

**앵커 스킴 변경:** `R01-Q03` → `G-S01-M02-Q03` (그린 1세트 2과목 3번)

등급 구분이 앵커에 반드시 들어가야 합니다. 그린과 블루는 **같은 세트명·같은 주제인데
문제와 정답이 다릅니다.** 등급을 빠뜨리면 엉뚱한 답을 근거로 답변하게 됩니다.

### 2-2. 객관식이 아니라 수행평가

"3번 답이 왜 ③인가요" 같은 선택지 문제가 아닙니다.

| 과목 | 형태 | 정답 |
|---|---|---|
| 1과목 콘텐츠 | 단답 5문항 + 제출파일(CSV 등) | 정수·한글 정확일치 |
| 2과목 데이터분석 | 단답 5문항 + 제출파일(보고서) | 정수·한글 정확일치 |
| 3과목 자동화 | **단답 없음.** 산출물(웹페이지·스크립트) | 루브릭 채점 |

3과목은 정답이 존재하지 않으므로 **삼각 검증이 성립하지 않습니다.** 질문 유형도
"이렇게 만들면 점수 되나요?"에 가까워, 근거는 정답이 아니라 채점 루브릭입니다.
→ 3과목은 별도 처리 경로가 필요합니다.

### 2-3. 문항 수가 적다 — 벡터 검색 불필요

단답 문항 총계: **2과목 × 5세트 × 2등급 × 5문항 = 100문항.**

100문항의 앵커·질문 요약 목록은 수천 토큰이면 전부 들어갑니다.
임베딩·벡터DB 없이 **목록을 통째로 주고 문항을 특정 → 해당 파일 로드**로 충분합니다.

→ [04-open-questions 2-3](04-open-questions.md) **결론: 단순 특정+조회.**
운영 자료(문항 구조 없는 긴 문서)만 별도 판단이 필요합니다.

## 3. PDF 추출기 이슈 (중요)

**pdfplumber가 일부 답안지에서 숫자를 통째로 누락합니다.**

블루 1세트 1과목 답안지에서 `문항`·`배점` 열과 제출파일 정답 CSV의 숫자가 전부 빈 값으로
추출됐습니다. `extract_tables()` 로도 동일하게 빈 셀입니다.

```
pdfplumber:  |  | 2 | 담당 부서 종류: ...        ← 문항·배점 소실
pypdfium2 :  1 15 2 담당 부서 종류: ...         ← 정상
```

**정답지에서 정답 숫자가 사라지는 것**이므로 그대로 쓰면 치명적입니다.

- 잠정 결정: 추출은 pypdfium2 기준. → **1단계 실행에서 부분 철회됨 (아래 참조).**
- pdfplumber는 폐기하지 않고 **대조군으로 유지** — 두 추출기 결과가 갈리는 지점이
  곧 변환 위험 지점이므로, 사람이 볼 곳을 자동으로 좁혀줍니다.

### 3-1. pypdfium2 도 답안지에서 틀린다 (1단계 실행 결과)

90개 PDF를 실제로 변환해 대조한 결과, **pypdfium2 역시 답안지에서 실패합니다.**
실패 방식이 pdfplumber와 반대입니다.

| 추출기 | 실패 방식 | 해당 |
|---|---|---|
| pdfplumber | 숫자를 통째로 **누락** | 5건 |
| pypdfium2 | 좁은 표 열에서 인접 셀 숫자를 **병합** | 2건 |

그린 3세트 2과목 답안지가 결정적입니다.

```
pypdfium2 (당초 기준)      pdfplumber (대조군)
문항 정답                   문항 정답
1                          1 3621
2                          2 22
3                          3 3
4                          4 생활편의
5                          5 1435
3621 223      ← 22와 3이 "223"으로 병합
생활편의 1435   ← 정답 5개 중 4개만 남음
```

여기서는 **pdfplumber가 완벽하고 pypdfium2가 표를 망가뜨렸습니다.**
블루 2세트 2과목도 같은 병합 사고입니다 (`15 4` → `154`, `5 0` → `50`).
같은 행의 비율 값(`0.2667` = 4/15)이 어느 쪽이 맞는지 검산해 줍니다.

**결론: 어느 한쪽을 단일 기준으로 삼을 수 없습니다.**

→ 답안지는 두 추출 결과를 **모두 마크다운에 싣고** 사람이 원본과 대조해 확정합니다.
프론트매터의 `verified: false` 로 미확정 상태를 추적하며, 확정 전에는 답변 근거로 쓰지 않습니다.
문제지·해설은 문맥이 있어 오류를 알아채기 쉬우므로 pypdfium2 단일 추출을 유지합니다.

두 추출기를 대조하는 구조가 아니었다면 이 사고는 발견되지 않았을 것입니다.

### 그 외 확인된 손상

- 좁은 표 열에서 글자가 세로로 쪼개짐 (`행 정 구 역` ← `행정구역`)
- 종합안내서(디자인 브로슈어)는 읽기 순서가 뒤엉킴 — 목차·본문이 섞여 추출됨

→ 1단계 완료 조건인 "원본 대조 검증"은 형식적 절차가 아니라 실제로 필요합니다.

## 4. 코드 실행 검증이 실제로 가능하다

2과목 해설에는 **정답 산출 전체 코드**가 그대로 들어 있고, 입력 CSV도 첨부로 함께 있습니다.

```python
# 해설.pdf에 실린 코드 (요약)
merged = pd.merge(df1, df2, on="기관코드", how="inner")
clean = merged.dropna()
...
print("문항3 행수 =", len(clean))   # 141
```

즉 2과목은 정답을 **추론이 아니라 실행으로** 확인할 수 있습니다.
블라인드 풀이의 신뢰도가 다른 과목보다 훨씬 높습니다.

### 즉시 얻을 수 있는 부수 산출물

첨부 데이터로 해설 코드를 실행해 답안지 숫자와 대조하면,
**기존 자료의 오류 목록이 챗봇 완성 전에 바로 나옵니다.**
설계 문서 [02-data 4장](02-data.md)의 "부수 산출물"을 지금 착수할 수 있다는 뜻입니다.

**검수 원칙:** 각 세트는 독립적으로 판정합니다. 세트 간 형식·난이도 차이는 오류가 아닙니다.

| 1세트 2과목 답안지 총인구수 정렬 오류(전북/전남) | **수정됨** — 전라남도 → 전북특별자치도 |
| 3세트 2과목 문제지·CSV 컬럼명 불일치 | **수정됨** — 봉사분야·봉사자유형으로 일치 |
| 3세트 3과목 해설 결과 수 10 vs 8 | 해설 오류로 확인 (3과목은 단답 없음) |
| **5세트 1과목 총점검건수 불일치 판정** | **미수정** — 위 6-2 |

→ 셀프학습 질문을 문항 특정 골드셋으로 쓸 때는 **질문 시점의 자료가 현재와 다를 수 있음**을
전제해야 합니다. 정확도를 그대로 측정하면 과소평가됩니다.

## 7. 운영 문의 이력 수령 (2026-08-03)

`[문의내용 정리] 2026년 데이터기반행정 역량강화.xlsx` — **13개 시트 8,694행.**

| 시트 | 내용 | 처리 |
|---|---|---|
| `AI챔피언자주하는 질문(25년~)` | **운영 FAQ 37건 — 실제 답변 원문** | **편입** (34건) |
| `FAQ` (13건) | 온라인 콘텐츠 공동활용 — 기관 담당자용 | 범위 밖, 제외 |

| 체크리스트·상담AP·일일보고 | 내부 운영 관리 | 제외 |

### 7-1. 읽을 시트를 이름으로 못박았습니다

기존 `extract_xlsx` 는 시트명에 `명단·연락처·선발…` 이 들어가면 건너뛰는 **블랙리스트**입니다.
이 워크북에는 그 방식이 통하지 않습니다 — `2-1.문의사항(Call)` 처럼 이름만으로는
무해해 보이는 시트가 실명·소속·휴대폰번호를 1,200행씩 담고 있고, 시트는 매달 늘어납니다.

→ 이 문서만 **화이트리스트**(`FAQ_SHEET`)로 읽습니다. 새 시트가 추가돼도 기본값이 "안 읽음"입니다.

FAQ 는 질문 한 줄을 섹션 하나로 만듭니다. 다른 운영 문서와 달리 **제목이 곧 질문 원문**이라
그 자체가 가장 정확한 조회 키이기 때문입니다 (`III AI 챔피언` 같은 무의미한 제목과 반대).
담당자 업무 루틴 행 3건(`문의 방법`·`1:1 게시판/메일`·`전화/문자`)은 응시자 답변이 아니라
제외했습니다 — 근거로 잡히면 "진동으로 해놓고 부재중 확인" 같은 내부 지침을 인용하게 됩니다.

**마스킹에서 드러난 결함 2가지를 함께 고쳤습니다.**

| 결함 | 증상 | 수정 |
|---|---|---|
| `대리`·`사원` 이 일반명사이기도 하다 | "후배의 **대리 신청**" → "후배의 [담당자]" — **질문 원문이 훼손** | 직함 뒤에 `님`·조사·괄호가 올 때만 실명으로 본다 |
| 앵커를 마스킹 **전** 제목으로 생성 | 실명이 앵커에 남을 수 있는 구조 | 마스킹 후 slugify |
| `databus@nia.or.kr` 도 가려짐 | 공식 문의처가 `[이메일]` — 답변 가치 상실 | `PUBLIC_CONTACTS` 예외 |

편입 후 재스캔: **연락처·이메일 유출 0건.** 카탈로그는 운영 섹션 85 → 119, 12.3K → 14.5K 토큰.

### 7-2. 문의 이력 2,046건은 아직 쓰지 않았습니다

챔피언 관련만 2026년 1,465건 · 2025년 581건으로, 기존 골드셋 151건의 13배입니다.
다만 그대로 쓸 수 없습니다 — 키워드 필터라 과탐지가 섞여 있고, 답변 셀에 응시자용 문장과
내부 처리 메모가 한 칸에 뒤섞여 있습니다. 활용 방향은 [04-open-questions](04-open-questions.md) 2-6.

### 7-3. 연도가 박힌 답변은 그대로 쓰면 틀립니다

FAQ 는 2025년에 작성됐고 일부 답변에 연도 특정 사실이 들어 있습니다
(예: 전직원 대상 교육의 기준을 "**2024년** 확정 정원"으로 안내).
지금 그대로 내보내면 오답입니다. 운영 담당자 확인 후 갱신이 필요합니다.
