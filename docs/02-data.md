## 1. 데이터 소스

| 구분 | 자료 | 형태 | 역할 |
|---|---|---|---|
| 학습 | 셀프스터디 문제 | PDF | **정답의 근거 (고정점)** |
| 학습 | 해설 | PDF | 검수 대상 / 대조군 |
| 학습 | 답안지 | PDF | 검수 대상 / 대조군 |
| 학습 | 첨부파일 | CSV·MD (수령) | 보조 근거 / 코드 실행 검증 입력 |

자료는 1차 수령분이 전부가 아니며 **계속 추가됩니다.** 인제스트는 재실행 가능해야 합니다.

## 2. PDF → 마크다운 전환

### 왜 전환하는가

| PDF 유지 | 마크다운 전환 |
|---|---|
| 매 질의마다 파싱 비용 발생 | 1회 변환 후 재사용 |
| 표·수식·코드 레이아웃 깨짐 | 코드블록·LaTeX·표 보존 |
| 부분 수정 어려움 | 오류 발견 시 해당 줄만 수정 |
| 버전 관리 불가 | git으로 이력 추적 |
| 토큰 낭비 | 필요한 문항만 정확히 로드 |

AI 과목 특성상 **코드·수식·표가 많고, 이는 PDF에서 가장 잘 깨지는 요소**입니다.

### 변환 리스크

**변환 자체가 오류를 만들 수 있습니다.** 코드 들여쓰기가 하나 깨지면 답이 바뀝니다.

→ 변환 결과를 원본과 대조 검증하는 단계를 반드시 거칩니다. (로드맵 1단계)

### 마크다운 구조

실제 자료가 **등급 × 세트 × 과목** 3층 구조라, 아래는 실사([05](05-data-survey.md) 2-1) 이후
확정된 형태입니다. 초기안의 `round-01/` 평면 구조는 폐기됐습니다.

```
content/
├── selfstudy/
│   └── green/               # green | blue
│       └── s01-청렴윤리모니터링/
│           └── m01-콘텐츠/   # m01 콘텐츠 | m02 데이터분석 | m03 자동화
│               ├── problems.md   # 문제 원문
│               ├── solutions.md  # 해설
│               └── answers.md    # 답안
└── operations/
    └── ...                  # 운영 자료
```

문항 단위로 앵커를 부여해 정확히 특정할 수 있도록 합니다.
객관식이 아니라 **단답 수행평가**이므로 선택지가 없습니다.

```markdown
## [G-S01-M02-Q03] 문제 3

문제 본문...

**정답 형식:** 정수
```

앵커 스킴 상세와 등급이 필수인 이유는 [03-roadmap](03-roadmap.md) "앵커 스킴" 참조.

## 3. 구글시트 스키마 (제안)

| 컬럼 | 내용 | 입력 주체 |
|---|---|---|
| 질문일시 | 질문이 등록된 시각 | 사람 |
| 질문자 | 질문한 사람 | 사람 |
| 질문 | 질문 원문 | 사람 |
| **상태** | `대기` → `검수대기` → `완료` / `반려` | 시스템·사람 |
| **분류** | `문제` / `운영` / `분류불가` | 시스템 |
| **답변초안** | 생성된 초안 | 시스템 |
| **근거** | 출처 (예: `G-S01-M02-Q03`, `OPS-준비안내-응시환경`) | 시스템 |
| **플래그** | `해설불일치` / `근거부족` / `분류불가` | 시스템 |
| **최종답변** | 승인·수정된 최종본 | 사람 |
| 검수자 | 승인한 사람 | 시스템 |
| 검수일시 | 승인 시각 | 시스템 |

### 초안과 최종답변을 분리하는 이유

두 칸을 나누면 **"AI 초안이 얼마나 그대로 통과되는지"** 를 측정할 수 있습니다.

이 수치가 자동화 범위를 넓힐지 판단하는 근거가 됩니다.
초안 그대로 승인되는 비율이 충분히 높은 유형부터 단계적으로 자동화를 확대할 수 있습니다.

### 상태 흐름

```
대기 ──(초안 생성)──> 검수대기 ──(슬랙에서 승인)──> 완료
                          │  ↑
                          │  └──(시트에서 수정)
                          │
                          └──(반려)──> 반려
```

승인은 슬랙 카드에서, 수정은 시트에서 이루어집니다 — [04](04-open-questions.md) 2-1.

이 스키마는 **시트 경로 전용**입니다. 유선 문의는 시트를 거치지 않고 웹 UI에서 즉시 처리되며,
필요 시 사후 기록만 남깁니다.

## 4. 부수 산출물: 기존 자료 오류 목록

기존 질의응답 전체를 파이프라인에 한 번 통과시키면,
**새 판단과 과거 답변이 갈리는 건들**이 목록으로 나옵니다.

이것이 그동안 잘못 나갔을 가능성이 있는 답변 후보입니다.
공식 해설에 대해서도 동일하게 적용됩니다.

챗봇 완성 여부와 무관하게 **그 자체로 즉시 활용 가능한 결과물**입니다.
