# 설계

## 1. 문제 정의

셀프스터디(AI 과목) 관련 질문과 운영 관련 질문이 구글시트에 쌓이고,
담당자가 매번 수기로 답변을 작성하고 있습니다.

여기에 세 가지 문제가 겹쳐 있습니다.

| 문제 | 영향 |
|---|---|
| 수기 작성 부담 | 반복 질문에도 매번 사람이 대응 |
| 과거 답변에 오답 존재 | 과거 답변을 그대로 재사용할 수 없음 |
| 공식 정답·해설에도 오류 존재 | 해설조차 근거로 무조건 신뢰할 수 없음 |

---

## 2. 설계가 세 번 바뀐 이유

이 기록을 남기는 이유는, **각 단계에서 무엇을 잘못 가정했는지**가
앞으로의 판단 기준이 되기 때문입니다.

### 1차 설계 (폐기)

> 과거 Q&A를 벡터 검색해서 유사한 답변을 찾아 반환한다.

**폐기 사유:** 과거 답변에 오답이 섞여 있음.
이대로 만들면 **기존 오답을 자동으로 재생산하는 시스템**이 됨.

### 2차 설계 (폐기)

> 문제 원문과 공식 해설을 근거로 답변한다. 과거 답변은 참고만.

**폐기 사유:** 공식 정답·해설에도 오류가 있음.
"해설을 믿는다"는 전제 자체가 성립하지 않음.

### 3차 설계 (현재)

> 신뢰 가능한 고정점은 **문제 원문 하나뿐**이다.
> 나머지 소스는 서로 대조해서 갈리는 지점을 찾아낸다.

---

## 3. 신뢰 계층

```
문제 원문           ← 유일한 고정점 (단, 문제 자체 오류 가능성은 남음)
  ├── 공식 해설·답안지   ← 검수 대상
  ├── 과거 답변          ← 검수 대상
  └── Claude 독립 풀이   ← 검증 수단
```

어떤 소스도 단독으로 신뢰하지 않고, **셋을 대조한 결과**로 신뢰도를 판정합니다.

## 4. 삼각 검증 구조

```
                    [문제 원문]
                         |
            +------------+------------+
            v            v            v
      1 Claude      2 공식 해설   3 과거 답변
      블라인드 풀이   (검수 대상)   (검수 대상)
            +------------+------------+
                         v
                     대조 판정
        +----------------+----------------+
    셋 다 일치        둘만 일치          전부 갈림
   신뢰도 높음      해당 소스 오류 의심   문제 자체 오류 의심
   초안 생성        초안 + 경고 플래그    초안 없이 사람에게
```

### 블라인드 풀이가 핵심

Claude에게 **해설을 보여주지 않고 문제만 주어 먼저 풀게 합니다.**

해설을 함께 주면 모델이 거기에 끌려가(anchoring) 해설의 오류를 잡아내지 못합니다.
풀이가 끝난 뒤에야 해설과 대조합니다.

## 5. 전체 워크플로우

질문은 **두 경로**로 들어옵니다 — 구글시트와 유선(전화). 둘 다 대응합니다.

```
        [시트에 질문 등록]          [유선 문의 — 전화받는 중]
                |                            |
                +-------------+--------------+
                              v
                       1) 질문 분류
                       +- 문제 관련 --> 문제/해설/답안지/첨부파일 조회
                       +- 운영 관련 --> 운영 자료 조회
                       +- 분류 불가 --> 초안 없이 사람에게
                              |
                              v
                       2) 답변 초안 생성
                          - 문제 관련: 블라인드 풀이 후 해설과 대조
                          - 근거 출처 명시 (앵커, 문서/페이지)
                          - 교재 기준 답 + 현재 기준 병기
                              |
                +-------------+--------------+
                v                            v
        [시트 경로 — 비동기]          [유선 경로 — 실시간]
                |                            |
        3) 시트에 '검수대기' 기록      3') 웹 UI에 근거와 함께 즉시 표시
           + 슬랙 카드 발송                  |
                |                     4') 담당자가 보고 판단해
        4) 검수: 슬랙에서 승인/반려,          구두로 답변
           수정은 시트에서                   |
                |                     5') 필요 시 시트에 사후 기록
                v
        5) 승인 -> 최종답변 등록, 상태 '완료'
```

**완전 자동 발송은 하지 않습니다.** 승인 게이트가 오답 발송을 구조적으로 차단합니다.

### 유선 경로에서도 승인 게이트는 유지됩니다

유선은 검수를 건너뛰는 경로가 아닙니다. **담당자 본인이 실시간 검수자**입니다.
챗봇은 근거와 함께 초안을 화면에 띄울 뿐이고, 사람이 보고 판단해서 구두로 전달합니다.
챗봇의 출력이 사람을 거치지 않고 질문자에게 도달하는 경로는 어디에도 없습니다.

### 유선의 추가 제약: 응답 시간

전화를 붙잡은 채로 블라인드 풀이와 삼각 검증을 처음부터 돌리면 느립니다.

→ 유선 경로는 **이미 검수 완료된 답변을 먼저 조회하고, 없을 때만 실시간 생성**합니다.
반복 질문일수록 즉답이 되고, 검수 완료본이 쌓일수록 빨라집니다.
이때 조회 대상은 **승인된 최종답변**이지 미검수 과거 답변이 아닙니다 — 3장 신뢰 계층이 그대로 적용됩니다.

## 6. 질문 분류

"문제 3번 답이 왜 이런가요"와 "과제 제출 기한이 언제인가요"는 근거가 완전히 다릅니다.
잘못 분류하면 엉뚱한 자료에서 답을 찾습니다.

실제 질문 151건을 분류해 본 결과, 당초 3분류(문제/운영/분류불가)로는 부족했습니다.
**근거가 없는 유형과 사람이 조치해야 하는 유형을 구분하지 않으면** 챗봇이 답하면 안 되는
질문에 초안을 만들게 됩니다. ([05](05-data-survey.md) 6장)

| 유형 | 실측 | 근거 소스 | 처리 |
|---|---|---|---|
| **문항** | 25 | 문제지·해설·답안지 | 앵커 특정 → 답변. 등급 불명이면 **되묻기** |
| **운영** | 64 | 준비안내·CBT가이드·FAQ | 근거 없으면 초안 생성하지 않음 |
| **자료요청** | 26 | — | **사람이 파일을 보내야 함.** 챗봇이 답할 성질이 아님 |
| **기술지원** | 16 | — | 도구 설치·계정 문제. 우리 근거 자료에 답이 없음 → 사람에게 |
| **교육내용** | 4 | — | 개념 질문. **일반 지식으로 답하지 않음** → 사람에게 |
| **무관** | 1 | — | 홍보·잡담. 무시 |
| 분류 애매 | 15 | — | 초안 없이 `분류불가` 플래그로 검수 요청 |

애매한 경우 **추측해서 진행하지 않습니다.**

### 문항 문의 안의 세부 유형

| 세부 유형 | 근거 | 처리 |
|---|---|---|
| 오답 원인 문의 | 문제지 처리 규칙 + 해설의 "흔한 오답" | 학생 답과 정답이 **갈린 지점**을 짚음 |
| 문제 오류 제기 | 문제·해설·답안지 삼각 대조 | **판정하지 않고** 대조 결과만 제시 → 사람에게 |
| 3과목 산출물 | 채점 루브릭 | 기준 안내까지만 ([04](04-open-questions.md) 2-3) |

### 등급 되묻기는 예외가 아니라 상시 동작입니다

문항 문의 25건 중 **16건이 등급(그린/블루)을 밝히지 않았습니다.** "3세트 2과목"까지만
적는 것이 보통이고, 그린과 블루는 세트명이 같으면서 정답이 다릅니다.

시트가 등급별로 나뉘어 있어 담당자는 맥락으로 알지만, **질문 텍스트만으로는 알 수 없습니다.**
되묻기를 예외 처리로 두면 안 되고, 문항 경로의 기본 동작으로 설계해야 합니다.

### 응시 방식이 질문 유형을 결정합니다

문제지에 **"허용 도구: AI 챗봇(ChatGPT · Claude · Gemini 등) 자유 활용"** 이 명시돼 있습니다.
교육생은 문제지와 첨부파일을 AI에 넣어 푸는 것이 정상 응시 방식입니다.

그래서 "정답이 뭐예요"는 주력 질문이 아닙니다. 학생은 이미 답을 갖고 있고,
**그 답이 정답과 다를 때** 묻습니다. 필요한 것은 정답 숫자가 아니라 갈린 지점입니다.

같은 이유로 **해설의 코드는 재현 수단으로서의 가치가 낮습니다** — 학생은 그 코드대로 풀지
않았을 것이고, 정답에 이르는 경로는 여럿입니다. 반면 해설의 **처리 규칙 서술과 "흔한 오답" 표**는
갈린 지점을 짚는 데 직접 쓰이는 핵심 자산입니다. 해설을 통째로 취급하지 말고 이 둘을 구분하세요.

### "문제 오류 제기"를 자동 판정하지 않는 이유

학생이 직접 "이거 문제가 틀린 것 같은데요"라고 제기하는 경우입니다.

- "오류가 맞다"고 잘못 답하면 → 멀쩡한 공식 자료를 부정하게 됩니다
- "오류가 아니다"라고 잘못 답하면 → 실제 오류를 덮습니다

양쪽 다 대가가 크므로 초안에 판정을 싣지 않습니다. 삼각 대조 결과와 근거만 정리해
사람에게 넘깁니다. 4장의 "전부 갈림 → 초안 없이 사람에게"가 이 경우입니다.

## 7. 문제 특정(identification)

검색보다 먼저 해결해야 하는 문제입니다.

학생이 "3번 왜 이래요?"라고 물으면, 먼저 **어느 교재 몇 회차 3번인지** 확정해야 합니다.
여기서 틀리면 그 뒤 모든 처리가 무의미합니다.

- 확정 가능 → 진행
- 애매함 → 되묻거나 `분류불가` 처리
- **추측해서 진행하지 않음**

## 8. 해설 오류 검수의 통합

당초 "해설 검수"를 별도 단계로 두려 했으나, 승인 게이트가 생기면서
**일상 운영 흐름에 통합**하는 것으로 정리했습니다.

초안에 다음과 같은 플래그를 함께 표시합니다.

> ⚠️ **해설 불일치** — 공식 해설은 3번을 정답으로 보지만,
> 문제 조건상 2번이 맞다고 판단됩니다. 확인 필요.

검수자가 이를 판단하면 **답변도 나가고 해설 오류도 함께 잡힙니다.**
별도 검수 프로젝트 없이 운영 과정에서 자료가 점진적으로 정화됩니다.

## 9. AI 과목의 특성

| 이점 | 내용 |
|---|---|
| 객관적 정답 존재 | 해석의 여지가 적어 검증 가능 |
| Claude의 도메인 강점 | 독립 풀이의 신뢰도가 높음 |
| **코드 실행 검증** | 코드 문제는 추론이 아니라 실제 실행으로 확인 가능 |

### 주의: 시점 충돌

AI 분야는 변화가 빠릅니다. 모델 성능 수치, 최신 아키텍처, 라이브러리 API 등은
교재 작성 시점과 현재가 다를 수 있습니다.

**정책 (확정): 교재 기준 정답 + 현재 기준 병기**

> 교재 기준으로는 A입니다. 다만 현재는 B로 바뀌었습니다.

평가·시험이 교재 기준으로 이루어지므로 교재 기준을 정답으로 하되,
학습자가 최신 정보도 함께 얻을 수 있도록 병기합니다.

---

## 10. 안전 원칙

1. 근거 없이 답하지 않는다 — 일반 지식으로 메우지 않음
2. 판단이 갈리면 초안을 만들지 않고 사람에게 넘긴다
3. 모든 초안에 근거 출처를 명시한다
4. **못 답하는 것은 괜찮지만, 틀린 답을 등록하는 것은 안 된다**
